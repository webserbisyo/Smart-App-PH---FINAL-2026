# UX rules

Read for every screen task. General rules only; each screen's prompt names its components.

- One nav per device: never a dock and a sidebar at the same time.
- Breakpoints by width; input sizes by pointer (`pointer: coarse` gets 44 px targets and 16 px text).
- Checkout and receipt are one column, max 640 px, at every width.

## 2. App-like feel on phones (both apps)

- `viewport-fit=cover` and `env(safe-area-inset-*)` padding under the dock, tab bar and cart bar (iPhone home bar). Viewport: `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content`; never `maximum-scale` or `user-scalable`.
- `100dvh`, never `100vh` or `h-screen`, so the address bar doesn't cut layouts.
- Inputs at 16 px so iOS doesn't zoom; `inputmode` and `autocomplete` on phone, email, OTP and money fields.
- Hide the dock and bars while the keyboard is open (`visualViewport`), so they don't ride on top of the keyboard; the main action bar sits above the keyboard.
- Bottom sheets (drawer) instead of centred dialogs on phones: item sheet, cart, sign-in, filters. Every sheet sizes itself, stays inside the screen and has exactly one scroll area.
- Press states (`active:`), hover only under `@media (hover: hover)`; no grey tap flash (`-webkit-tap-highlight-color: transparent`); `touch-action: manipulation`.
- Page changes: View Transitions (React `<ViewTransition>`), fade and rise 8 px, off under reduced motion.
- Instant-feeling navigation: TanStack Router `preload: 'intent'`, Next `<Link>` prefetch, skeletons in the shape of the content, optimistic buttons.
- `theme-color` meta per shop (storefront) and for the dashboard; `overscroll-behavior: contain` in sheets.
- PWA install, offline page and icons come with the storefront install task (Serwist, decision T6).

## 3. States (every screen)

Loading skeleton · empty with one line and one action · error with Try again · offline · closed or paused shop · keyboard open · long text (one line with ellipsis on cards, full in sheets and detail) · big amounts (`₱12,345.50` fits, prices never wrap) · dark mode (dashboard). Lists end with a footer, not blank space.

## 4. Accessibility

- AA contrast (4.5:1 text, 3:1 borders, focus rings and chart marks); a visible focus ring on every control.
- Icon-only buttons have an `aria-label` and a tooltip.
- Fields have a label and an error linked by `aria-describedby`.
- Checkout and every form work with the keyboard alone; sortable lists move with Space and Enter.
- `<title>` per route (the item name, not "Edit"); `lang` set.
- Charts: one y-axis, a tooltip and one screen-reader sentence.

## 5. Layout and input

- One filled button per screen; main actions at the bottom in thumb reach; Cancel and Delete small, inside a More menu.
- A disabled button says why ("You're offline", "Closed now", "Choose a size"). Hide options that can't apply (for example payment methods an order type doesn't allow).
- Forms in groups of 5 to 7 fields; each settings section saves on its own.
- Destructive actions confirm with a reason. Order steps only move forward; the one exception is Recall, shown for 5 seconds after a step (the server allows 10; decision T51).
- Forgiving input: phone accepts 0917…, 917… or +63…; money accepts "₱120" and "120.50"; references ignore spaces.
- Toasts: bottom centre above the dock on phones, top centre on desktop (decision R36); semantic colours (green, red, amber, blue), never shop colours (R35); success closes after 3 s, errors stay; at most one action.

## 6. Screen notes (rules, not components)

**Storefront**

- Home: banners (up to 3), announcement, reward card or "Join and get 1 free stamp", categories, best sellers, About, hours and contact. A closed shop says so and add buttons say why.
- Menu: sticky search and categories; "+" adds at once when there is one variant and no required add-ons, otherwise opens the item; sold-out items stay, greyed; `?item=<id>` opens an item.
- Item: required choices first; a missing one scrolls to it and the button says what to choose; single choice shows radio rows with "+₱", 2 or 3 choices use toggle group chips per axis with "+₱<delta>" (T46); note up to 120 characters.
- Cart: saved on the device per shop; missing or sold-out lines are flagged and left out of the total.
- Checkout: one page (how, who, pay); re-quoted before Place order; pickup slots start 20 min out, today or tomorrow, inside hours; a closed shop with "Take orders while closed" on offers next-opening slots for pickup and delivery (N1); offline keeps the cart and details and Place order waits for the connection (N2); transfers show "Send exactly ₱345" with Copy.
- When picker (O6, How and where sheet and checkout): ASAP or Schedule cards; ASAP is off when the shop can't start now or an item needs notice, and then the earliest open time is picked for the customer to change. Day chips (Today, Tomorrow, then "Thu 29"; up to 14, More dates beyond) say Closed, Full or Too soon and can't be tapped; time chips grouped Morning, Afternoon, Evening, Full ones struck through. A time that fills up is replaced and the picker says so; a slot_unavailable at Place order reopens the sheet on that day. No open day: "Fully booked until" plus Message the shop.
- Receipt (O6): the 4-character pickup code under the QR ("Show this at pickup") and the scheduled time; the thermal slip prints both.
- Receipt: big order number, live status (15 s poll fallback), upload proof → "Checking your payment" → rejected reason with Upload again; Save receipt (image) and Print or Save as PDF (N11); "ORDER SLIP · NOT AN OFFICIAL RECEIPT" on slips; install card after the first order.
- Account: 6-digit code with a 60 s resend timer; stamp card; confetti once when a reward is ready.

**Dashboard**

- Owner auth: narrow card, show/hide password, reset by code (no links), Setup, Pending and Suspended screens. Shop status re-checked every 30 s and on focus.
- Orders (T54): one page, one toolbar row (Board/List, search by name, number or pickup code, sound bell with a dot when off, Busy, ⋯ with Order times and the dev scenarios). Type cards under it with icon, word, count and total; no "All" (tap again to clear); "To check" in amber while transfer proofs wait; Delivery hides when the shop doesn't deliver. Open-order count in the nav badge and the tab title ("(N) Orders · <Shop>"). Board on phones: a sticky stage strip in stage colours (New, Preparing or Packing, Ready, Out) and one stage's cards, "+N later today" under New; the first card starts near 250 px on a 390 px phone. Board from 768 px: ReUI Kanban with live drag (the target column tints, columns the order can't go to fade, a refused drop springs back with the reason), stage colour bar, count and total in each head, and a Done rail with today's count and total that opens the List. Forward skips allowed (T55); Recall toast for 5 s after every step except Done. Expired unpaid transfers leave the board the moment the pay window ends. New orders fade in with a 2 s ring and the chime.
- List view (T54, replaces History and Scheduled): Today, Yesterday, Pick a date (no future dates) and Upcoming (every later day, grouped by day with a count and total); status chips with counts (only the ones that have orders); the installed data grid from 768 px (order and type icon, time, customer with member chip, item photos and count, total, payment chip, stage chip) and tappable cards on phones; footer with count and sales (cancelled and expired don't count); empty states say what to do (Show today, Clear filters).
- Change time: Opens from the order panel ⋯ menu; WeekStripCalendar for near days (≤14 days) and Popover Calendar for further dates; booking slot grid with Full and Too soon badges; "Allow anyway" switch to override slot limits; saves only on confirm; disabled with informative notice when offline; updates receipt and logs order activity.
- Print ticket: from the order panel's ⋯ menu; the browser print dialog prints only the ticket (print rules in `globals.css`), black on white in any theme, monospace, 58 and 80 mm: shop, number and type, due time (with the date when not today), customer name, every line with variant, add-ons and notes, order note, total and payment word, the receipt QR and the pickup code in large letters.
- Order panel (T54): opens from any card or row at once with what the board already has, then fills in; a Sheet from the right from 768 px (the board stays behind it) and a Drawer from the bottom on phones; `?order=` in the address so Back closes it and links share; `/orders/<id>` redirects here. Pinned header (type, stage chip, big number and total, placed time, time chip, pickup code with Copy), then steps in stage colours with times and minutes between, payment (proofs with Approve and Reject, Mark as paid for pay-later), items on the thermal slip, customer with Call and Message, rider for delivery, owner note, activity. Pinned footer: one main button for the next step (or the lock reason while a transfer waits) and ⋯ with Move to (every later step), Change time, Print ticket and Cancel order.
- Home (T69 to T71): greeting and story line, setup checklist until done, Needs you (hidden at 0, worst first), Today (sales against "a usual <weekday>" in words only: Ahead, About usual, Behind), Hour by hour against a usual day, On the board with Next up, Best sellers, How they ordered and paid, Members today, Coming up, Last 7 or 30 days (change in % against the days before), When you're busy (4-week map). No date pickers; an empty new day looks calm.
- Menu or Products: 4 tabs (Items, Categories, Add-ons, Variants); Visible and Sold out switches inline; reusable variant templates per shop; items link to a variant template or use custom choices; up to 3 choices and 30 combinations (T46); each choice priced independently (item base price + option price changes) with a "Same price for all options" switch; combinations computed in background with optional overrides and sold-out per combo; shared add-on groups with min and max, "Goes well with" up to 4 items; up to 5 photos; an item with orders is archived, not deleted; leave guard on unsaved edits.
- Members: list with segments, member detail with stamp history, manual stamp ±1 with a reason (at most 3 per member per day), stamp card, claims (N5).
- Editor (T72 to T75): opens full screen outside the shell (N13). The real shop Home in a live preview (Phone 390 or Laptop 1280, scaled to fit); tap a part on the page or in the list to edit it, and the page scrolls to it and outlines it. Parts follow the page top to bottom (Look; Banners, Announcement; Stamp card, Categories, Best sellers, Favourites; Hours and contact, About, Members count), each with what it shows now and a switch. The draft saves by itself with the status in the top bar (Live, Saving, Draft saved · n changes, offline, failed, conflict); Publish lists the changes first; Discard asks first; Undo and Redo 50 steps. Look: name, tagline, logo, palettes from the logo, Tap your logo, any colour, Light or Dark, page colour, 60/30/10 strip with contrast checks. Phone: full preview, bottom bar Sections · Colours · Publish, the picked part docked under the preview so the page stays in sight.
- Insights: hidden for launch (T69); `/insights` opens Home's Last 7 or 30 days. The full page comes back in Blueprint B.
- Settings (T64 to T68): three groups, Your shop (Shop with contact facts, Hours, Ordering, Delivery, Payments), You (Account with the avatar, Appearance, Notifications) and Plan and storage (Plan, Storage). The index shows a status line per section; each section has one Save bar and a leave guard; laptops show a "Customers see" preview. Every owner photo goes through one upload step that says what changed ("4.2 MB → 180 KB · WebP"). Storage shows the 500 MB pool, cleanups that ask first and a ZIP export.

## 7. Dashboard brand rules (decision T35)

- One solid blue (`primary`) element per view: the main action or the hero number. Everything else neutral.
- Phone: one primary and at most one secondary button per screen; frequent actions in a sticky bottom bar (48 px), destructive ones in menus, away from the thumb.
- Mint (`member`) means stamps and rewards only, never success or links; success is the darker green.
- Status is colour, icon and word together; red and green states always differ by icon shape too.
- Money and counts use `tabular` and right-align in tables; weights 400 body, 500 labels, 600 headings, 700 only for numbers.
- The logo gradient (`brand-gradient`) only on the logo, the login band, the loyalty strip and the reward moment; never behind text, on buttons or as gradient text.
- Depth with `elevation-*`, at most two levels on screen; motion with `ease-enter` / `ease-exit` and the duration tokens, transform and opacity only; one 500 ms celebration (`duration-celebrate`) when a stamp card fills.
- The stamp card is the one tactile part (decision T36): 2 px border, dashed empty slots, solid mint filled slots with a navy icon, a pop when a stamp fills.
- No glass panels: blur only on the top bar and dock (`frost`). No animated backgrounds, count-up money or looping effects in the dashboard.

## 8. Dashboard feedback rules (decision T43)

Every dashboard page follows these, so an owner always knows what happened.

- **Toasts:** one toaster for the whole dashboard (`AppToaster` in `App.tsx`), top right on desktop, above the dock on phones (at the top while a sheet is open). Show a toast for a change away from where the owner tapped (menu actions, bulk actions, archive, restore, hide, move, delete, duplicate), for any error not tied to a field, and whenever there is an Undo. No toast when the result already shows where they tapped (a switch, a drag, a button that turns into a check). Success closes after 3 s, errors stay until closed, at most 3 on screen, one action each.
- **Buttons that wait for the server:** `AsyncButton` (c-button-44 pattern, `packages/ui/src/compositions/async-button.tsx`): the verb, then a spinner with "Saving", then a check with "Saved" for a moment, then the button returns. Save never moves the owner (T47): a sheet closes, a page stays. Same width in every state, disabled while busy, announced to screen readers. Used for every Save, Add, Delete, Remove, Move and crop.
- **Copy:** `CopyButton` (c-button-41 pattern): copy icon, then a check and "Copied" for 1.5 s. No toast. Copy through `copyText` (`packages/ui/src/lib/copy-text.ts`), which has a fallback for plain http links; if both ways fail, say how to copy by hand (T44). Show the word, not only the icon, when there is room.
- **Toast placement:** on phones, while a sheet, drawer or the bulk bar is open, toasts drop in at the top so they never cover its choices; on the dashboard desktop they sit at the top right (T44, T45).
- **One action, no menu:** a ⋯ menu needs at least two actions; a single action is a labeled button (basket Clear empties at once with Undo in the toast, T45).
- **Confirm or Undo:** reversible actions (archive, hide, sold out, move, restore, bulk) happen at once with Undo in the toast. Actions that cannot be undone (delete, delete forever, remove samples, delete a category with items) ask first with a solid red button that names the action. Never both.
- **States:** loading is a skeleton in the page's layout; empty and error use `PageEmpty` and `PageError` (shadcn Empty) with one line and one action (Add, Try again); offline, warnings and save errors use `Notice` (DiceUI Banner); field errors sit under the field (shadcn FieldError) and Save scrolls to the first one; item states use DiceUI Status (icon, word, colour).
- **Words:** buttons are short verbs; while busy the same verb with -ing ("Deleting", never "Saving" on a delete); done in past tense with the name when short ("Saved Classic Smash", "1 item archived"). Errors say what to do next, worded from the error code. All in `words.ts` (`actionWords` for button states).
- **Flows stay in place (T47):** Save keeps the owner where they are; a new record becomes its own page. A sheet opened inside a page (a new category, add-on group or variant from the item editor) saves only itself and returns there with the result picked. Lists keep their search, filter and scroll (search params plus the router's scroll restoration), and Back returns to the page the owner came from when it is under the same parent. After an add or edit, the saved row or card is outlined for a moment. In a form, Enter moves to the next field; only the Save button saves. Full-screen edit pages hide the phone dock.
- **Restore:** an archived item comes back hidden, with "Show now" in the toast, so it never reaches customers by surprise. Only an item nobody ever ordered can be deleted forever.
